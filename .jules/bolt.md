## 2025-02-14 - Optimize sequential count queries using UNION ALL
**Learning:** In SQLAlchemy, executing multiple independent `await db.execute()` queries sequentially on the same session for dashboard aggregations (e.g., getting counts of different entities like Papers, Notes, Presentations) causes unnecessary latency due to multiple database round-trips. SQLAlchemy `AsyncSession` explicitly prohibits concurrent queries on the same session, meaning `asyncio.gather()` cannot be used here to parallelize them without managing separate database sessions.
**Action:** When a FastAPI endpoint requires aggregating independent metrics (e.g., multiple counts), combine them into a single `UNION ALL` query using `sqlalchemy.union_all` and `sqlalchemy.literal` to label each row. This resolves the N+1 latency problem and fetches all dashboard statistics in one efficient round-trip.
